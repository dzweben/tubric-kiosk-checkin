Overview

The Challenge: Multiple labs collect overlapping participant data, creating duplicate records, inconsistent IDs, and unsafe sharing of identifiable information.

The Solution: A single kiosk‑driven intake flow that standardizes participant data, generates stable GUIDs, and pushes harmonized records to REDCap while maintaining an IRB‑safe de‑identified export path.

System Architecture

1
Single Point of Entry
Participant or guardian completes a unified check‑in flow across labs/projects.
↓
2
Identity Resolution + Stable GUID
DOB‑first matching with name/email/phone validation to prevent duplicates; GUID is created or reused.
↓
3
Harmonized REDCap Push
Creates new records or appends repeat visits and contact updates to existing records via API.
↓
4
IRB‑Safe De‑ID Export
A parallel de‑identified export supports cross‑project coordination without exposing PHI.

API Integrations

  • REDCap API — Record lookup by GUID, repeating‑instrument imports, and harmonized record updates
  • Local CSV Source‑of‑Truth — Canonical storage for matching, repeat visits, and contact updates
🔐 Security Notice: API tokens remain local and are never embedded in the UI. All REDCap actions are executed via saved scripts in the repository.
